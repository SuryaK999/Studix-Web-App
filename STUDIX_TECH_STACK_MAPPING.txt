1. THE MERN FOUNDATION (The Core)
---------------------------------
* M - MONGODB ATLAS:
  - Role: Idi mana "Main Database".
  - What it stores: User accounts, Study Room profiles, Channel structures, 
    and permanent Chat history.
  - Why: Study rooms lo chala data untadi, documents and channels structures
    flexible ga store cheyadaniki "NoSQL" database kavalai, and MongoDB is the best!

* E - EXPRESS.JS:
  - Role: Idi server-side "Traffic Controller".
  - What it does: Mana API endpoints handle chestadi. Frontend(React) nundi
    vache queries ni database (MongoDB) tho connect chestadi.
  - Why: Node.js tho kalisi fast ga and lightweight ga work chestadi.

* R - REACT.JS (VITE):
  - Role: Idi "User Interface (UI)".
  - What it does: User kallaki kanabade buttons, pages, and interactive rooms.
  - Why: React allows us to build "Components". Vite enduku ante adi normal
    create-react-app kante 10x fast ga project build and run chestadi.

* N - NODE.JS:
  - Role: Idi "The Runtime Engine".
  - What it does: Back-end processing logic run chestadi.
  - Why: Idi synchronous kakunda "Asynchronous" (non-blocking) ga work 
    chestadi, so multiple users chat chestuna hang avvadu.

2. HYBRID REAL-TIME TOOLS (Special Powers)
------------------------------------------
* SOCKET.IO:
  - Role: The "Real-time Messenger".
  - What it does: Chat messages, typing indicators, and room activity ni 
    fraction of seconds lo broadcast chestadi.
  - Why: HTTP request-response kakunda, idi "Direct Tunnel" (Websockets) open 
    chestadi server and client madhya.

* UPSTASH REDIS:
  - Role: High-speed "Status Checker".
  - What it does: Evaru online unnaaro "Green Dot" status ventane chupistadi.
  - Why: Status checking kosam MongoDB ki velli chustu kurchunte app slow
    avtundi. Redis "In-memory" (RAM lo) store chestadi kabatti ultra-fast.

* FIREBASE FIRESTORE:
  - Role: Secondary "Low-Latency" Database.
  - What it does: Group tasks sync cheyadaniki and AI-chat history kosam.
  - Why: Tasks lo okaru check-mark kottina ventane andariki sync aypovali, 
    deeni kosam Firestore is very fast compared to Mongo.

* FIREBASE AUTH:
  - Role: Secure "Login Gatekeeper".
  - What it does: Login, Signup, and Google Authentication handle chestadi.
  - Why: Manam manually secure codes raase kante, industry-standard Google
    provided security (Firebase) vadadam safe.

* SUPABASE STORAGE:
  - Role: Cloud "File Cabinet".
  - What it does: PDF notes, User profile photos, images store chestadi.
  - Why: File storage mana main server meeda load padakunda bayata cloud
    provider meeda upload chestunnam.

4. DOUBT CLEARING QUESTIONS (Viva/Interview Prep)
-------------------------------------------------

Q: Em use chesav project lo unique ga?
A: "Sir, memu 'Hybrid DB Architecture' vaadam. Heavy data ki MongoDB, 
   real-time task-syncing ki Firebase vaadam."

Q: Project lo 'Redis' enduku vachindi?
A: "Redis in-memory store sir. Presence tracking (who's online) logic kosam 
   DB calls kante Redis caching valla performance 10x perugutundi."

Q: Collaborative notes lo okaru type chesindi vere vallu delete cheste?
A: "Conflict-free Replicated Data Types (CRDTs) using Yjs vaadam sir. 
   Adi users actions ni mathematically merge chestundi, so conflicts ravu."

Q: Vite enduki vaadaru standard React badulu?
A: "Vite uses 'esbuild' and 'ES modules'. Idi development speed and 
   building faster bundles load cheyadam lo support chestadi."

Q: Supabase and Firebase rendu enduku?
A: "Firebase authentication and real-time triggers kosam baguntundi. 
   Supabase efficient cloud-storage (S3 compatible) storage kosam vaadam."

5. VOICE CHANNEL (Audio Communication Layer)
--------------------------------------------
* WEBRTC (Web Real-Time Communication):
  - Role: The "Direct Audio Engine" (Browser Native).
  - What it does: Enables Peer-to-Peer (P2P) direct audio streaming between
    users in the same voice channel without routing voice data through our server.
  - Capabilities:
    * Ultra-low latency voice transmission (Uses UDP protocol).
    * Built-in echo cancellation and noise suppression.
    * High-quality Opus audio codec support natively.
  - Why: Server meeda heavy audio stream load padakunda, users direct ga connect 
    avvadaniki WebRTC is the best industry standard.

* SOCKET.IO (Signaling Server for Voice):
  - Role: The "Call Operator" & "Handshake Manager".
  - What it does: Voice call start ayye mundu users valla IP/Port details 
    (SDP offer/answer & ICE Candidates) exchange cheskovali. Socket.IO ee 
    signaling chestadi.
  - Why: We already have Socket.IO for chat, so it acts as the perfect bridge 
    to establish the WebRTC voice connection seamlessly.

* ALTERNATIVE STACK (If using Cloud Providers like Agora / LiveKit):
  - Role: The "Managed Cloud Audio Hub" (SFU/MCU Architecture).
  - What it does: Handles massive group voice calls where P2P becomes complex.
  - Why: If many students (20+) join a single voice channel, WebRTC P2P mesh 
    network lags. Platforms like Agora Web SDK offload audio routing to cloud servers.
